# Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A push to `master` on GitHub runs a CDK Pipeline. The pipeline tests and builds one image and one SPA bundle, deploys dev and then QA, and deploys prod after a manual approval. Each environment sits behind its own WAF web ACL, on its own `*.cloudfront.net` URL. Each distribution stays eligible for the CloudFront flat-rate Free plan and is subscribed where the account allows it.

**Architecture:** `infra/environment.py`, renamed from `proof_dev.py`, defines `EnvironmentStack`, the existing dev stack made per-environment. It also defines `EnvironmentStage`, a CDK `Stage` that pairs `EnvironmentStack` in `us-west-2` with `EdgeStack` (`infra/edge.py`) in `us-east-1`. `EdgeStack` holds only the web ACL, and the two stacks are joined by `cross_region_references`. `infra/pipeline.py` defines `PipelineStack`, a `pipelines.CodePipeline` whose GitHub source is read through a CodeConnections connection. It adds one `EnvironmentStage` each for dev, QA, and prod, with a `ManualApprovalStep` before prod. `app.py` builds only the pipeline stack. After one hand deploy of that stack, the pipeline deploys everything, including itself.

**Tech Stack:** AWS CDK v2 (`aws-cdk-lib` 2.278 locked, Python), `aws_cdk.pipelines`, `aws_wafv2.CfnWebACL`, CDK CLI 2.1149.0, `uv` 0.13.9, `pytest` with `aws_cdk.assertions`, CodeBuild `STANDARD_7_0` (the CDK Pipelines default), Node 26, and Go 1.27.4 (fetched by `GOTOOLCHAIN=auto`).

**Spec:** T007 and T008 in `TODO.md`. [ADR 0001](../adr/0001-serverless-go-platform-architecture.md), as amended 2026-11-23, covers Decisions 3, 4, 8, and 10, the cost baseline, and the settled open questions 2–4. ## Global Constraints

- Environments are exactly `("dev", "qa", "prod")`, in that order. Stack names are `environment_name(projectName, env)` and `environment_name(projectName, env) + "-edge"`. The pipeline stack and the pipeline are both `f"{projectName}-pipeline"`.
- The Hosted UI prefix stays `environment_name(projectName, env)` (ADR 0003).
- `HOME_REGION = "us-west-2"`. Only `EdgeStack` is in `EDGE_REGION = "us-east-1"`, and it holds only the web ACL plus CDK's cross-region-reference plumbing.
- `swb-proof-dev` keeps every existing logical id, so the pipeline updates the hand-deployed stack in place. Its pool, users, prefix domain, client, bucket, distribution, and API are not replaced.
- Each distribution stays flat-rate Free plan eligible: it has a web ACL, a cache policy (no `ForwardedValues`), and an origin access control (no OAI). It has no CloudFront Functions and no real-time logs. Its web ACL has at most 5 rules and no customer rule groups.
- Web ACL rules, by priority: `RateLimit` (0, rate-based, limit 1000 per 5 minutes per IP, block), then `AWSManagedRulesAmazonIpReputationList` (1), `AWSManagedRulesCommonRuleSet` (2), and `AWSManagedRulesKnownBadInputsRuleSet` (3), each with `OverrideAction: None`. Default action allow. CloudWatch metrics and sampled requests on. No WAF logging.
- Log groups: `RetentionDays.ONE_MONTH` with `RemovalPolicy.DESTROY` in dev and QA, and `RetentionDays.SIX_MONTHS` with `RemovalPolicy.RETAIN` in prod. Prod User Pool: `RemovalPolicy.RETAIN` and `deletion_protection=True`. Dev and QA pools keep `DESTROY`.
- One synth per commit. The synth step runs Go, web, and infra tests, then `npm run build`, then `cdk synth`. Every stage deploys the same assets. Each environment's `config.json` still comes from `Source.json_data` in its own stack.
- Prod deploys only after `ManualApprovalStep("PromoteToProd")`. Dev and QA have no approval.
- `infra/cdk.json` context adds `repository` (`owner/name`) and `connectionArn`. Both are checked at synth and named in the error.
- Non-test Python follows `AGENTS.md`: Napoleon docstrings with only the sections that apply, and `#:` on module globals, class attributes, and `__init__` attributes.
- Logs never contain the email or the ID token.

## Review Focus

1. **The pipeline replaces dev's User Pool when it adopts `swb-proof-dev`.** A changed construct path or id would give the pool a new logical id. CloudFormation would then create a new pool, which fails while the old one holds the prefix, and the existing users would be lost. Pinned by `test_dev_keeps_its_hand_deployed_logical_ids` (Task 1), and checked again with `cdk diff` in Task 4.
2. **A distribution silently loses Free plan eligibility.** This happens if someone adds a CloudFront Function, legacy cache settings, an OAI, a sixth WAF rule, or a rule group. Subscription is then refused, or the plan cannot stay on. Pinned by `test_distribution_is_flat_rate_eligible` and `test_web_acl_fits_the_free_plan` (Task 2).
3. **Prod deploys without approval, or QA waits for one.** Pinned by `test_dev_then_qa_then_approved_prod` (Task 3).
4. **Environments run different bytes**, for example because of a per-stage rebuild or a per-stage asset. QA would then not have tested what prod runs. Pinned by `test_every_environment_deploys_the_same_assets` (Task 3). The existing `test_dev_config_is_never_uploaded` still guards the local `config.json`.
5. **Deleting prod's stack deletes its users or its logs.** Pinned by `test_retention_and_removal_by_environment` (Task 1).

Synth cannot check the following, so Task 4 does:

- The arm64 image builds on x86 CodeBuild. The Dockerfile cross-compiles, and its arm64 stage has no `RUN`, so no emulation should be needed.
- A real distribution update, not a no-op deploy, keeps the web ACL attached and, where subscribed, the Free plan (Task 4, Step 10).
